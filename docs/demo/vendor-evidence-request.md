# Vendor Evidence Request

Practice: **Family Dental Clinic**

Purpose: request BAA, security, incident-notification, retention/deletion, subprocessor, and AI data-use evidence without treating any vendor as approved.

## Safety Boundary

Do not send PHI, patient identifiers, credentials, private admin URLs, raw logs, patient screenshots, full private contracts, or incident-sensitive details.

## Requested Vendor Evidence

| Evidence | Acceptable proof | Question | Unsafe inputs |
|---|---|---|---|
| Vendor security evidence status | SOC 2 status label; HITRUST status label; vendor security page; gated proof request status; reviewer note | Request vendor security evidence status and route private proof to the appropriate reviewer. | PHI or patient identifiers; credentials; private admin URLs; raw logs; patient screenshots; full private contracts |
| Vendor incident and data lifecycle terms | incident notice term summary; retention term summary; deletion or export capability note; subcontractor or subprocessor list status | Request incident-notification, retention, deletion, export, and subcontractor term status from each relevant vendor. | PHI or patient identifiers; credentials; private admin URLs; raw logs; patient screenshots; full private contracts |
| AI data-use and model-training terms evidence | model-training setting; data retention term summary; deletion/export capability note; human review workflow; reviewer note | Request AI data-use, retention, model-training, and human-review evidence before expanding restricted workflows. | PHI or patient identifiers; credentials; private admin URLs; raw logs; patient screenshots; full private contracts |

## Vendor Language

Use public evidence, gated proof, missing evidence, and professional review recommended. Do not treat this request as vendor approval, legal advice, or authorization for PHI use.
